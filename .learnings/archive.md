# 棚卸の記録

## 棚卸の手順

- **起動条件**: active が12件を超えたとき、または change のアーカイブ時
- **判定**: 引用0件かつ3 change 経過 → 削除を提案 ／ 引用3件以上 → 昇格を提案（テスト・lint・config へ） ／ それ以外 → 継続
- **削除の承認は人間**が行う。判断材料は `active.md` の各エントリ2行目（出来事）にある
- 引用数は `git log --grep "Learning: LNN" --oneline | wc -l` で数える
- **観測値**: `active.md` は 5件で 1992 バイト、8件で 3418 バイト（門ではない。段階2に進むかの判断材料）
- 削除・昇格したものは下に理由付きで残す。**同じ学びが後で再捕捉されたら、削除規則が厳しすぎる信号**として扱う

## 昇格

### アクセント色を反転したら文字色も反転する

- **昇格先**: コントラストの回帰テスト（未実装。別 change として立てる）
- **理由**: 採用基準4「コードやテストに書けない」で落ちた。書けるので、より強い層に置く
- **出来事**: change 1 で、ダークモード用に明るいコーラル（`#ff7a7f`）へ変えたのに文字色を白のまま残し、保存ボタンのコントラストが 2.52:1 になった（基準は 4.5:1）。ライトモードだけ確認して報告していたため気づかなかった
- **昇格が完了したら**: この項目に「実装済み」と追記する。未実装のまま3 change 経過したら、昇格の出口が機能していない信号として扱う

## 却下

### `rm` の対話モード（別の言い回し）

- **理由**: L01 と同内容のため統合。重複

### npm overrides の入れ子構文が効かない

- **理由**: 採用基準2「次も確実に遭遇する」と基準3「再導出にコストがかかる」の両方で落ちた
- **出来事**: change 1 で `{"@esbuild-kit/core-utils": {"esbuild": "^0.25.0"}}` と書いたが適用されず、パッケージごと `npm:tsx@^4` へ差し替える必要があった。ただし遭遇は1回きりで、`npm ls` を見れば適用されていないことはすぐ分かる

### 偽物を注入したテストは、置き換えた本物を検証しない

- **昇格先**: カバレッジ計測（未実装。`vitest --coverage` を `cron-worker` も含めて回す）
- **理由**: 採用基準4「コードやテストに書けない」で落ちた。0% として機械的に出るので、判断ではなく計測に置く
- **出来事**: change 4 のレビューで、Web Push の応答分類（404/410 を期限切れとする処理）がどのテストからも一度も実行されていないと指摘された。送信関数を偽物に差し替えたテストは集計しか見ておらず、分類を丸ごと壊しても緑のままだった
- **昇格が完了したら**: この項目に「実装済み」と追記する

### ゲートは、作った時点でしか検証していない

- **昇格先**: CI（未実装。push ごとに `npm test` を素で実行する）
- **理由**: 採用基準4で落ちた。「毎回自分で走らせる」は規則にしても守られない。自動実行に置き換えられる
- **出来事**: change 3 で「テストが通らないとデプロイしない」ゲートを作り、終了コード1で止まることまで実証した。その後 change 4 で `cron-worker/node_modules` が増え、vitest の除外 `node_modules/**` がルート直下しか一致しないため wrangler 同梱のテストを拾い、`npm test` が恒久的に赤になった。レビューで指摘されるまで気づかず、その間ゲートは空回りしていた
- **昇格が完了したら**: この項目に「実装済み」と追記する

### Web Push の 403 を期限切れ扱いにしない

- **理由**: 採用基準2「次も確実に遭遇する」で落ちた。Web Push の応答コードという一度きりの領域知識で、コード側のコメントとテストに書けば足りる（`lib/push.test.ts` に固定済み）
- **出来事**: change 4 のレビューで、VAPID の設定ミスが 403 を返すため、403 で購読を削除すると鍵を直しても二度と届かなくなると指摘された
