# 学び

- 学びは「**規則** + **それを生んだ出来事**」で書く。規則だけの記述は残さない（出来事がないと、後で残すか消すかを判断できない）
- 学びを適用したコミットには `Learning: LNN` の行を1つ足す
- 12件を超えたら棚卸を起動する（手順は `.learnings/archive.md` の冒頭）

- **[L01] `rm` は `-f` を付けて呼ぶ**
  このマシンの zsh は `rm` が対話モードにエイリアスされている。change 1 で確認待ちに気づかず、コマンドが2分間ハングしてタイムアウトした。
  破棄が確実な場面では `rm -f` を使う。

- **[L02] 既存ファイルの上書きは `>|`**
  `noclobber` が有効なため `cat > file` が「file exists」で失敗する。change 1 で2回踏み、どちらも heredoc の中身が丸ごと実行されずに黙って消えた。
  上書き意図があるときは `>|` を使う。

- **[L03] headless Chrome の配色切替は CDP で行う**
  `--blink-settings=preferredColorScheme` も `--force-dark-mode` も効かず、ライト用とダーク用に撮った2枚がバイト単位で同一（219056 bytes）になった。フラグは静かに無視される。
  `Emulation.setEmulatedMedia` を CDP 経由で使う。

- **[L04] 配色の性質を主張する前に実測する**
  ダークモードを「暖色ベースにした」と報告したが、レンダリング結果から色相を測ったら背景は257＝紫だった。意図と結果が逆方向だった。
  主張の前に、計算値で確かめる。

- **[L05] spec のシナリオはブラウザで一通り辿る**
  単体テスト18件が全て緑でも、空白のみで保存を試した後のエラーが1001文字入力時にも残り続ける欠陥があった。ブラウザでシナリオを順に辿って初めて見つかった。
  実装が終わったら、spec のシナリオを画面上で1つずつ確認する。

- **[L06] 検査は、違反をわざと入れて赤くなるまで検査ではない**
  change 3 で、実鍵が履歴に無いことを見る grep が `.env.example` のプレースホルダ自身に一致し、`createRouteMatcher` を禁じる検査がその上のコメントに一致した。2回とも常に緑で、何も守っていなかった。
  検査・ゲートを書いたら、守りたい違反を1つ注入し、赤くなることを確かめてから採用する。

- **[L07] 環境依存の値は、自分の環境と符号や桁が違う値をテストに入れる**
  change 4 の cron が日境界を自前計算しており、UTC+9 では正しいまま Pacific/Auckland で1440分ずれた。テスト入力が全て `Asia/Tokyo` だったため、東京で動かす限り永久に出ない欠陥だった。
  タイムゾーン・ロケールのように環境で変わる入力は、自分の環境の値だけで固めない。

- **[L08] `- [x]` を付ける前に、そのタスク本文の検証条件を読み直す**
  change 4 のタスク1.2「同じ購読先を2回保存しても1件になることをテストで確認する」に完了印を付けたが、保存コードもテストも存在しなかった。レビューで指摘されるまで進捗は誤った数を示していた。
  タスクに書かれた検証条件を実際に満たしたときだけ完了にする。

- **[L09] 検査を走らせる前に、自分の変更が検査の入力に入っているか確かめる**
  change 5 で、履歴を走査する鍵の検査を**コミット前に**実行して「OK・終了コード 0」と報告した。走査対象は git の blob なので、直前に足した `.env.example` の行はまだ入っておらず、コミットした瞬間から常に赤になった。レビューで指摘されるまで気づかなかった。
  検査が何を入力にしているか（作業ツリーか、コミット済みの履歴か）を見て、必要なら先にコミットしてから走らせる。
