## Why

学びを記録する仕組みがないために、同じ失敗を繰り返している。change 1（`add-memo-capture`）だけでも、`noclobber` による上書き失敗を2回、headless Chrome の配色切替の誤りを3回踏んだ。どちらも再導出にコストがかかり、エラーメッセージからは原因が分からない種類の知識だった。

参考にできる前例がある。このプロジェクトは以前 AI-DLC という方法論を使っており、**そこには既に学習記録の仕組みが存在した** — `project.md` の `## Corrections` セクション、`<!-- cid:stage:cN -->` による出所追跡、§13 admission gate まで揃っていた。AI-DLC 自体は OpenSpec を学ぶために置き換えられたのであって、この仕組みが機能不全で捨てられたわけではない。したがって「仕組みを作れば解決する」でも「軽くすれば解決する」でもない。

ただし運用して分かった**明確な欠点が1つある**。「この学びを残しますか？」と確認されたとき、**学びの記述が人間に理解できる形になっておらず、判断がつらかった**。実際に残っている5件はいずれもこの形をしている。

```
- 選択肢が選ばれなかったことを、その反対を選んだと解釈しない。除外リスト
  （Won't Have 等）で選ばれなかった項目は、要件やバックログに載せる前に
  優先度を明示的に問い直す。 (learned 2026-07-29)
```

一般化された命令文だけで、**何が起きてこの規則が生まれたのかが書かれていない**。これでは「そんなことがあったか」「本当に問題だったのか」「また起きるのか」のどれにも答えられない。判断材料がないまま判断を求められる状態であり、これが棚卸を苦痛にしていた。

この change の設計目標は、その欠点を繰り返さないことである。**記録する学びは、後から人間が「残す価値があるか」を判断できる形でなければならない。** 判断できない記録は、蓄積されるほど棚卸を機能不全にする。

## What Changes

- **`.learnings/active.md` を新設する。** 学びの置き場。`CLAUDE.md` から `@import` され毎セッション読まれる。
- **学びは「規則 + それを生んだ具体的な出来事」の形で書く。** 一般論だけの記述を禁じる。これが AI-DLC の仕組みとの実質的な差分であり、棚卸を判断可能にする唯一の手段である。
- **採用基準を4つ設ける。** 4つ全部を満たすものだけ記録する（具体的な出来事がある／次も確実に遭遇する／再導出にコストがかかる／コードやテストに書けない）。
- **件数がしきい値（12件）を超えたら棚卸を起動する。** 硬い壁ではなく起動条件。学びが際限なく増えて文脈を圧迫することを防ぎつつ、価値ある学びが入口で弾かれることも避ける。
- **引用は commit trailer で行う。** `Learning: L05` の1行。追加の手間がゼロで、git に永久に残り、grep で集計できる。
- **評価の時計を「アーカイブされた change の数」にする。** 経過日数ではない。趣味のプロジェクトは3週間触らないことがあり、カレンダー時間では生きている学びを誤って削除する。
- **ライフサイクルの出口を2つ用意する。** 使われなければ削除、よく使われれば昇格（テスト/lint/config へ）。どちらも active から出ていくので、ファイルは一方的に膨らまない。
- **`.learnings/index.json` と `.learnings/archive.md` を新設する。** どちらも文脈には読み込まない。前者はメタデータ、後者は削除・昇格したものの記録。
- **初期5件の学びを投入する。** change 1 で得られた候補8件を採用基準にかけ、採用5件・昇格1件・却下2件になったもの（選別の実例は design.md に記載）。

### 今回やらないこと

最小構成だけで一度回してから足す。**この change のスコープは段階1のみ**であり、以下は明示的に対象外とする。

- **段階2（今回やらない）**: `.learnings/review.mjs`（git ログ集計、削除/昇格候補の提示）、`npm run learnings:review`、`openspec/config.yaml` の `operations.archive.guidance` への追記。段階2に進むかは、段階1の棚卸が実際に回るかを確認してから決める。
- **段階3（今回やらない）**: `.claude/settings.json` の `Stop` フック、種別タグによる条件付き読み込み。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

なし。

この change は Remoru という製品の機能ではなく、開発プロセス／ツールの変更である。利用者から観測可能な製品の振る舞いは一切変わらない。仕様は振る舞いを記述するものであり、振る舞いが変わらない以上、変わるべき仕様もない。したがって `.openspec.yaml` に `skip_specs: true` を設定し、spec デルタは作らない。バリデーションを通すために要件をでっち上げることはしない。

## Impact

- **新規ファイル**: `.learnings/active.md`、`.learnings/index.json`、`.learnings/archive.md`
- **変更ファイル**: `CLAUDE.md`（@import の1行追加のみ）
- **製品コードへの影響**: なし。アプリケーションのソース、スキーマ、API、依存関係のいずれも変更しない
- **依存関係の追加**: なし。段階1はツールを必要としない
- **コミット規約への影響**: 学びを適用した際に commit trailer `Learning: LNN` を1行足す。既存のコミットメッセージ形式とは競合しない
- **文脈サイズへの影響**: 毎セッション `active.md` の分だけ増える。出来事を併記するぶん1件あたりは長くなるが、判断可能性はそのコストに見合う。際限ない増加は件数しきい値と棚卸で抑える
