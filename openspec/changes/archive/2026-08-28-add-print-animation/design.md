## Context

動機は proposal.md を参照。要件は `specs/motion/spec.md` と
`specs/memo-capture/spec.md`。

案は3つ作って実機で比べた（[刷り見本](https://claude.ai/code/artifact/5c945629-8dda-440b-9c01-53a3de7e655d)）。

| 案 | 中身 | 結果 |
|---|---|---|
| A 版が合う | 橙の版がずれて着地し重なる | 見送り |
| B 送り | 入力欄の文字が抜け、行が差し込まれる | 見送り |
| **C 刷り上がり** | 左から右へインクが載る＋指の位置から波紋 | **採用** |

C の詰めも見比べた（[下の行はどう下がるか](https://claude.ai/code/artifact/98c66a2a-d786-4132-a552-985b29d55200)）。
下の行がカクッと下がる C1 ではなく、**高さも一緒に開く C2** を採る。

いまの実装で効いてくる制約が3つある。

1. **一覧は `MemoTab` ごと unmount される**（タブの切り替えとメモの詳細）。
2. **一覧は生成中に取り直される**（`app-shell` が最大8回）。
3. `prefers-reduced-motion` で動きを止めると、change 10 では2つの状態が
   同じ丸になった前例がある。

## Goals / Non-Goals

**Goals:**

- 書きとめた手応えを、300回目にも耐える形で出す
- 既にある行の位置が飛ばないようにする
- 動きを止めた人にも「加わった」が伝わる

**Non-Goals:**

- 音・振動（iOS の PWA では `navigator.vibrate` が使えない）
- 削除・タグ付け・復習など、他の操作への動きの追加
- 問答ができた瞬間（③）の演出。**別の打点なので、この change では触らない**

## Decisions

### D1: 刷りは「高さが開く」→「インクが載る」の二段にする

行がいきなり全高で割り込むと、下の行が**1フレームで**ずれる。高さを開けば、
紙が差し込まれて場所ができる形になる。

```
0ms         高さが 0 から開きはじめる
 60ms       インクが左端から入る
200ms       高さが開ききる（下の行はここまで滑る）
480ms       インクが右端まで抜ける
```

**高さは実測する。** 本文は最大1000文字で、行の高さは中身で変わる。
固定値を置くと、長い本文で途中が切れるか、短い本文で余白が跳ねる。

```
list.prepend(row)
row.getBoundingClientRect().height  ← 動かす前に測る
--h に入れて 0 → var(--h) を animate
```

測ってから動かす順序が要る。先にアニメーションを付けると 0 を測ってしまう。

### D2: 合図は mount ではなく「いま書いた1件」

mount を合図にすると、**タブから戻ったときに全行が刷り直される**。一覧は
`MemoTab` ごと unmount されるので、戻るたび6件が順に刷られることになる。

生成中の取り直し（最大8回）では行はキーで再利用されるため mount は起きない
が、**unmount の経路が別にある**以上、mount には頼れない。

いま書いた1件の id を `app-shell` が憶える。下書き・タグの提案・告知の答えと
同じ場所で、`app/unmount-boundary.test.ts` の4件目になる。

| 過去に踏んだもの | 症状 |
|---|---|
| 書きかけの本文 | 詳細を開くと消えた |
| タグの提案 | 消えた（取り直しに課金が要る） |
| 告知の答え | 答えたのに問いに戻った（change 11） |
| **刷りの合図** | **戻るたび全行が刷られる**（この change） |

**一度刷ったら印を消す。** 印を残したままにすると、同じ行が2回目の
unmount でまた刷られる。

### D3: 演出は保存を待たせない

行は保存の応答が返った時点で直ちに現れ、演出はその上で起こる。演出の完了を
待って次を受け付ける形にはしない（`motion` の要件）。

続けて書かれた場合、**前の行の演出が終わっていなくても次の行が入る**。
高さのアニメーションは行ごとに独立しているので重なっても破綻しないが、
実機で「続けて3件」を確かめる（モックでは 260ms 間隔で確認済み）。

### D4: 動きを止めたら、橙の版を1本残して引く

動きを消して何も残らない形にしない。新しい行の左に橙の版（`box-shadow:
inset 3px 0 0`）を出し、0.4 秒おいて 1.2 秒かけて引く。

**位置の移動ではなく色の減衰**にする。動きを減らしたい人が避けたいのは
大きな移動であって、状態が変わったことを知る手段まで失いたいわけではない。

change 10 では点滅を止めた結果、「作成中」と「予定あり」が同じ塗りつぶした
丸になり、残る違いが色相だけになった（グレースケールで 1.16:1）。同じ轍を
踏まないよう、**止めたときに何が残るかを先に決める**。

### D5: 波紋は押した位置から出す

`pointerdown` の座標から円を広げる。ボタンの中心からではなく**指の位置から**
出すことで、押したのが自分だという手応えになる。

`pointerdown` を使うのは、`click` を待つと押してから発火までに間が空くため。

## Risks / Trade-offs

- **`clip-path` のアニメーションは合成が効かない場合がある** → 行は1つだけ、
  高さも小さい。実機で確かめる。重ければインクの層（`::before` の
  `translateX`）だけ残して `clip-path` を落とす。
- **`mix-blend-mode` はダークで `screen` に反転する**（既存の規則）。
  インクの層も同じ扱いにしないと、暗い地で色が沈む。
- **長い本文の行は高さが大きく、200ms では速すぎるかもしれない** → 高さに
  応じて尺を変えることはしない。**尺が中身で変わると、繰り返したときに
  リズムが揺れる**。一定にする。
- **演出の対象を取り違えると全行が刷られる** → D2。検査で固定する。
