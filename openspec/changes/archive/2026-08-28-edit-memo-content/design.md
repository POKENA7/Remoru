## Context

動機は proposal.md、要件は `specs/`。案は実機で比べて N を採った
（[メモ本文の編集](https://claude.ai/code/artifact/6ed91498-a306-4691-a7c7-1f6a3ee77153)）。

いま直せるものと直せないもの:

| | 直せるか | 消したときの巻き添え |
|---|---|---|
| タグ | ○ | — |
| 問と答 | ○（change 13） | — |
| **本文** | **×** | 消すと問答と復習の記録も消える |

`quiz_items` は `memos` を参照し、`review_schedules` は `quiz_items` を参照して
いる（どちらも cascade）。**本文を直したくて消すと、進み具合まで失う。**

既にあるもの:

- `validateMemoContent`（`lib/memos.ts`）— 空白のみを拒み、1000文字で切る
- `replaceQuizText`（`lib/quiz-items.ts`）— 問と答を書き換える。予定に触れない
- `QuizSheet` — 作成と書き直しの2経路を持つシート（change 13 D6）

## Goals / Non-Goals

**Goals:**

- 本文を直しても、それまでの復習が残る
- 本文を直したとき、古くなった答えが目に入る
- 直す場所を1つにする

**Non-Goals:**

- 直した履歴を残すこと（元に戻す機能は作らない）
- 一覧からの編集（詳細に置く）
- 本文を直したときに問答を作り直すこと（AI 再生成は change 13 でやめた）

## Decisions

### D1: 1つのシートで本文・問・答を直す

**本文を直すと、そこから作った答えが黙って古くなる。**

```
本文  近所のパン屋は火曜定休  →  水曜定休 に直す
問    パン屋の定休日は？          そのまま
答    火曜                        ← 嘘になったまま残る
```

次の復習で、間違った内容で自分を訓練することになる。自動では直せない
（生成のやり直しはやめた）ので、**直すべきものが目に入る場所に置く**。

3案を比べた。

| 案 | 鉛筆 | 古い答え |
|---|---|---|
| M 鉛筆を2つ | 本文と復習に1つずつ | 気づけない |
| **N ひとつの鉛筆で全部**（採用） | 上の帯に1つ | 目の前にある |
| O 本文の鉛筆が問答も連れてくる | 本文の隣に1つ | 目の前にある |

### D2: 鉛筆は上の帯へ。**画面に鉛筆は1つだけ**

change 13 では復習の見出しの隣に置いた。本文まで直せるようになると、
鉛筆が指すのは復習ではなく**このメモ全体**になるので、見出しの隣は狭すぎる。

```
←                    ✏  消す     ← 鉛筆はこのメモ全体を指す
近所のパン屋は火曜定休
復習
問  パン屋の定休日は？
答  火曜
次は 8月29日
```

上の帯に2つ並ぶが、**性格が分かれている**（青の印＝直す、赤い文字＝消す）。
change 13 で消すに `--danger` を当てたので、混ざらない。

### D3: 問答が無いメモでは、本文だけを出す

問と答をまだ持たないメモ（生成に失敗した、生成中）でシートを開くと、
問と答の欄が空になる。そこで作らせると、**「問と答をつくる →」と導線が
二重になる**。

```
問答あり  → 本文・問・答（3欄）
問答なし  → 本文だけ（1欄）。作成は既存の導線に任せる
```

### D4: 保存は2つに分ける。**本文が通ってから問答を書く**

本文と問答は別の表にあり、まとめて書く手段が無い（D1 と同じ制約が
`review_events` にもあった ― D1 は対話的トランザクションを持たない）。

| 順序 | 途中で落ちたとき |
|---|---|
| 問答 → 本文 | 問答だけ新しくなり、本文が古いまま。**答えが本文と食い違う** |
| **本文 → 問答**（採用） | 本文だけ新しくなり、答えが古いまま。**もう一度開けば直せる** |

どちらも中途半端になるが、**後者は画面を開き直せば気づいて直せる**。前者は
本文が正しく見えるので、食い違いに気づけない。

変更が無い側は書かない。本文だけ直した場合、問答への `PUT` は投げない。

### D5: 本文を直しても、復習の進み具合は変えない

`memos` の `content` だけを書き換える。`quiz_items` にも `review_schedules`
にも触れない。change 13 と同じで、**触らないことが担保そのもの**になる。

消して書き直すと進みが失われるので、これを避けることがこの change の
目的そのものである。

## Risks / Trade-offs

- **生成中に本文を直すと、生成が古い本文から作られる** → 生成は走り出した
  時点の本文を読む。できあがった問答が古ければ、同じシートで直せる。
- **問だけ直したいときも3欄出る** → 直すものが1画面に揃うほうを採った
  （D1）。欄は3つでも、触らなければそのまま保存される。
- **元に戻せない** → 履歴は持たない。復習の進みを守ることが目的であり、
  文言の版管理はこのアプリの役目ではない。
