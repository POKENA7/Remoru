design.md の Risks 参照。このグループが終わった時点で「ブラウザに画面が出る」ところまで到達させ、手応えのない時間を短くする。

- [x] 1.2 `wrangler.jsonc` に D1 バインディングを追加してローカル D1 を作成し、Workers ランタイム上（`npm run preview` 相当）でも同じページが表示されることを確認する

## 2. データ層

- [x] 2.1 `memos` テーブルのスキーマを定義する（`id` / `userId` / `content` / `createdAt`）。`userId` は認証導入まで固定値で埋める前提とし、その旨をコード上のコメントで残す
- [x] 2.2 マイグレーションを生成してローカル D1 に適用し、テーブルが作成されたことを `wrangler d1 execute` での参照により確認する
- [x] 2.3 インメモリ SQLite に対してスキーマを適用するテスト用ヘルパを用意し、ヘルパ自体のテストが通ることを確認する

## 3. メモの投入と取得

spec の `メモの投入` および `メモの一覧表示` 要件に対応する。この層に spec のシナリオをテストとして写す。

- [x] 3.1 本文のバリデーションを実装し、空・空白のみ・1000文字超がいずれも拒否されることをテストで確認する
- [x] 3.2 メモを保存する処理を実装し、保存時刻が記録されることをテストで確認する
- [x] 3.3 メモ一覧を取得する処理を実装し、保存時刻の新しい順で返ること、および保存直後のメモが含まれることをテストで確認する

## 4. API

- [x] 4.1 `POST /api/memos` を実装し、正常系で保存されること・バリデーション違反が拒否理由とともに返ることを確認する
- [x] 4.2 `GET /api/memos` を実装し、保存済みメモが新しい順で返ることを確認する

## 5. 画面

spec の `投入から一覧への即時反映` 要件に対応する。画面遷移を挟む実装にしないこと。

- [x] 5.1 入力欄と一覧を単一画面に配置し、保存済みメモが本文と保存時刻とともに新しい順で表示されることを確認する
- [x] 5.2 保存後、画面遷移も手動の再読み込みもなしに一覧の先頭へ反映されることをブラウザ上で確認する
- [x] 5.3 保存失敗時に、失敗を操作した場所で示しつつ入力欄の内容が保持され、再実行できることを確認する（保存処理を一時的に失敗させて検証する）
- [x] 5.4 メモが0件のときに空であることが分かる表示になり、最初のメモを投入できる状態であることを確認する
