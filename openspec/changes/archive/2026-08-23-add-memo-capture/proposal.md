## Why

現時点でアプリケーションコードは1行も存在しない。この change の目的は機能を出し切ることではなく、**成功指標①「メモ投入のしやすさ」を実際に手で触って判断できる状態を最短で作ること**にある。

先行する取り組みでは、設計成果物は積み上がる一方で動くものが一度も現れず、「これは自分の求めているアプリに向かっているのか」を確認できないまま時間が経過した。その再発を防ぐため、最初の change は「見て判断できるもので終わる」ことを最優先し、範囲を意図的にメモの投入と一覧に絞る。

## What Changes

- プロジェクトの足場を新設する（Next.js App Router + Cloudflare Workers/OpenNext + D1 + Drizzle ORM + Vitest）
- メモを1件保存できるようにする（自由記述のテキスト1つ）
- 保存済みメモを新しい順で一覧表示する
- ローカル開発環境（`wrangler` のローカル D1）で完結して動作する

この change に**含まれないもの**（後続の change で扱う）:

| 除外するもの | 扱う change |
|---|---|
| 問／答のペア、スケジューラ、出題、自己採点 | change 2 |
| 認証、本番デプロイ、PWA シェル | change 3 |
| プッシュ通知 | change 4 |
| 問答の AI 自動生成 | change 5 |

破壊的変更はない（初回のため）。

## Capabilities

### New Capabilities

- `memo-capture`: 利用者が日常の断片を自由記述で投入し、投入済みのものを一覧で確認できること。この capability は「投入」と「一覧」のみを担い、投入されたメモがその後どう復習されるかには関与しない。

### Modified Capabilities

なし（この change が最初の capability を導入する）。

## Impact

**コード** — リポジトリ全体。コードが存在しない状態からの新規作成となるため、この change の作業量の大半は足場の構築が占める。画面としては入力欄と一覧のみ。

**データ** — `memos` テーブルを新設する。認証は change 3 まで導入しないが、`userId` 列を最初から置き、固定値で埋める。change 3 でマイグレーションではなく配線の変更だけで認証を接続できるようにするための措置であり、`docs/intent-statement.md` の「技術的にマルチユーザー対応で設計する」という前提とも整合する。

**依存関係** — `next`、`@opennextjs/cloudflare`、`wrangler`、`drizzle-orm`、`drizzle-kit`、`vitest` を新規に導入する。

**秘密情報** — この change では認証も外部 API も扱わないため、シークレットは一切不要。公開リポジトリ上での秘密情報の取り扱いは change 3 以降の論点となる。

**未決定事項への影響** — `docs/intent-statement.md` の「Assumptions & Open Questions」に挙がっている未決事項（スケジューリングアルゴリズム、問答の作り方、通知経路、公開時期）は、いずれもこの change の範囲外であり、ここでは決定しない。
