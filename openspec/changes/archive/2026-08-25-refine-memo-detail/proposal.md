## Why

メモ詳細に2つ、実際に触ると困る形が残っている。

**1. タグを付ける道が2本ある。** いまは「入力して作る」と「候補から選ぶ」が
別々の仕掛けとして縦に並んでいる。同じ結果に2つの道があり、どちらを使えば
よいのか利用者が判断させられる。

```
タグ
 (生活) 外す
 [ つけかえる          ] [ つける ]   ← ①新しく作る道
 (仕事)(健康)(医療)(家電)(読書)(雑貨)  ← ②既存から選ぶ道
```

Notion の Multi-select はこの2つを**1つの操作に畳んでいる**。打つと候補が
絞り込まれ、一致するものが無ければその場で作れる。「作る」と「選ぶ」の
境目を利用者に意識させない。この考え方を借りる。

**2. 削除の確認が、押した指の真下に出る。** 実測すると、「消す」と
「ほんとうに消す」が**完全に同じ位置**（x=16 y=420）に現れる。

```
「消す」         x=16 y=420 幅 44
      ↓ 押す
「ほんとうに消す」 x=16 y=420 幅157
```

**続けて二度触れると消える。** 取り消せない操作で最もやってはいけない形で、
change 7 のレビュー（中-2）で「やめる」を足したときに、位置までは直して
いなかった。

## What Changes

**タグ**

- 入力欄と候補列を1つの選び手にまとめる。**欄に触れると候補が開く**
- 打つと候補が絞り込まれる。完全に一致するものが無ければ、最後に
  **「◯◯」をつくる**が出る
- いま付いているタグは印として出し、**×** で外す
- 別に「つける」ボタンは置かない。候補の行と「つくる」の行が、そのまま
  確定の手段になる

**削除**

- 確認を**シートで出す**。問と答の作成ですでに使っている形に揃える
- **押した場所と実行のボタンが離れる。** 二度続けて触れても消えない

## Capabilities

### Modified Capabilities

- `tagging`: タグの付与について、**新しく作ることと既存を選ぶことを単一の
  手段で提供する**ことを要件にする
- `memo-capture`: 取り消せない操作の確認について、**起動した場所と同じ位置に
  実行の手段を置かない**ことを要件にする

どちらも「実装の形」ではなく、**触ったときに何が起きるか**の話なので spec に
置く。書かないと、また同じ形に戻る（削除の位置は現に一度戻っている）。

## Impact

- `app/memo-detail.tsx`: タグの選び手と削除の確認
- `app/globals.css`: 候補の一覧、削除の確認シート
- データ層・API に変更は無い。`setTag` は名前を受け取る形のままで、
  **新規作成と既存の選択をすでに1つの入口で扱っている**（`findOrCreateTag`）。
  画面がそれに追いついていなかった
- 復習・通知・絞り込みへの影響は無い
