## Context

動機と実測値は `proposal.md`、要件は `specs/` を参照。

**制約1: 1メモ1タグ**（change 6 D2）。Notion の Multi-select は複数選択だが、
借りるのは**複数選べること**ではなく、**「作る」と「選ぶ」を1つの操作に畳んで
いること**である。

**制約2: 実クリックが確かめられない環境がある**（`.learnings` L10）。
新しい選び手は指で触る操作そのものなので、**確認できていない範囲を明示して
実機に委ねる**前提で作る。

**制約3: 説明文を増やさない**（change 8、`docs/design-decisions.md`）。
新しい UI に使い方の説明を添えない。触れば分かる形にする。

## Goals / Non-Goals

**Goals:**

- タグを付ける道を1本にすること
- 二度触れただけでメモが消えない状態にすること
- 文言を増やさずに済ませること

**Non-Goals:**

- 複数タグ。1メモ1タグは維持する（緩めるのは `MAX_TAGS_PER_MEMO` の1箇所）
- タグの名前の変更・削除・並べ替え
- 一覧側の変更。この change はメモ詳細だけを扱う

## Decisions

### D1: 印を押すと選び手が開く

普段はいま付いているタグの印だけが出ている。**その印を押すと、探す欄と
候補が開く。** タグを持たないメモには `＋ タグ` の印を出す。

3案をモックで比べて利用者が選んだ。**「押すと開く」ことに気づけるかが
唯一の懸念**だったが、印に `×` が付いているので押せるものだと分かる、
という判断。change 8 で説明文を減らした直後なので、ここに「押すと変え
られます」とは書けない——**形そのものが手掛かりになっている必要がある。**

`×` は外す、それ以外の場所は開く。当たり判定を分ける。

**閉じるのは3通り**——候補を選んだとき、`Escape`、選び手の外に触れたとき。

*代替案*: 欄を常に出しておく（案A）。却下。閉じているときも縦を1つ使い、
画面が静かにならない。
*代替案*: 下からシートで開く（案C）。却下。削除の確認もシートにするので、
**性格の違うものが同じ見た目で2つ**出ることになる。候補が多すぎる問題は
まだ起きていない（いま7件）。

### D2: 「つくる」は完全一致が無いときだけ、一覧の最後に出す

打った名前が既存のタグと完全に一致するなら、そのタグが候補に出ているので、
**作る手段は出さない**（spec の要件）。同じ名前のタグが2つできる余地を
画面から消す。

前後の空白は落として比べる。`lib/tag-text.ts` の `validateTagName` と
同じ正規化を使う。**画面と保存で判定がずれると、「つくる」を押したのに
既存が選ばれる**（あるいはその逆）ことになる。

### D3: 確定のボタンを別に置かない

候補の行と「つくる」の行が、そのまま確定の手段になる。**押せる的が
必ず画面にある**ので、change 6 で踏んだ「確定する手段が無い」（L10）は
起きない。

`Enter` でも確定できるようにする——完全一致があればそれを選び、無ければ
作る。キーボードの利用者に候補まで移動させない。

*代替案*: 「つける」ボタンを残す。却下。候補を選ぶときには使わない
ボタンが常に居座り、道が2本に見える元に戻る。

### D4: 削除の確認はシートで出す

問と答の作成ですでに使っている形（`sheet-backdrop` + `sheet`）に揃える。
利用者の判断。

**要点は見た目ではなく位置。** 起動した「消す」は画面下の左端、確認の
「消す」はシートの中。**指の真下が入れ替わらない**（spec の要件）。

*代替案*: 確認を「消す」の下に出して位置をずらす。却下。画面が伸びた
ぶんだけずれる形なので、伸び方によっては重なる。距離が保証されない。

*代替案*: 長押し。却下。長押しできることを説明する文が要る。制約3 と逆を向く。

### D5: 削除中はシートを閉じない

`消しています...` の間、シートは開いたまま。閉じてから結果が分かる形に
すると、失敗したときに**どこで失敗したのかが分からなくなる**。失敗したら
シートの中に出し、押し直せるようにする（change 7 で `res.ok` を見る形に
直したのと同じ考え）。

## Risks / Trade-offs

- **[候補が開くことに気づかない]** 欄に触れるまで何も見えない → 欄の
  プレースホルダを手掛かりにする。**説明文は足さない**（制約3）。
  実機で分かりにくければ「常に開く」に倒す
- **[候補が多いと画面を覆う]** いまは7件。増えたときは高さに上限を置いて
  中でスクロールさせる。上限を先に入れておく
- **[`Escape` が無い環境]** スマホには `Escape` が無い → 欄の外に触れれば
  閉じる。候補を選んでも閉じる。逃げ道は複数ある
- **[シートが増えて画面の層が深くなる]** メモ詳細（全画面）の上にシート →
  問と答の作成もすでに同じ深さで出ている。新しい形ではない
- **[実クリックを自分で確かめられない]** 制約2 → 確認できた範囲と
  できていない範囲を分けて報告し、実機に委ねる

## Migration Plan

1. タグの選び手を作り替える
2. 削除の確認をシートにする
3. コントラストと当たり判定を実測する
4. デプロイして実機で確かめる

**ロールバック**: 画面だけなので前の版に戻せば足りる。データにも API にも
触らない。
