## Why

change 1 と 2 でメモの投入から復習までのループは動くようになったが、**まだ手元の localhost にしかない**。この製品の判断で最も重要な問いに、まだ答えられていない。

> 日常に入れて、習慣として続くか

change 2 の proposal にも書いたとおり、自分で開きに行く復習と、通知に呼ばれる復習は体験として別物である。前者の手応えは得られたが、それは「明確にダメではない」までしか意味しない。**手元のスマホに置いて毎日触れる状態にして初めて**、この製品が生活に入るかどうかが分かる。

もう一つ理由がある。**先行実装（`remoru-implementation` ブランチ）はここで止まった。** 15タスク・44テストすべてを完成させながら、認証の実キーを入れず、一度もデプロイせず、実機で動かさないまま放棄された。README には「プレースホルダーのままでは全ページが HTTP 500 を返す」と書かれている。**一度も画面が表示されたことのない完成品**だった。

同じ地点を越えることが、この change の本質である。機能を足すのではなく、動くものを自分の手元に届ける。

## What Changes

- **Clerk による認証を導入する。** サインイン・サインアップ・サインアウト。公開サインアップとし、誰でもアカウントを作れる
- **固定利用者を実際の利用者に差し替える。** `SINGLE_USER_ID` を参照している箇所を、認証済みセッションから導出した識別子に置き換える。データ移行は発生しない（`userId` 列は change 1 から存在する）
- **利用者ごとのデータ分離を、認証の上で成立させる。** 他の利用者のメモ・問答・復習に一切到達できないこと
- **PWA シェルを追加する。** manifest とアイコン。ホーム画面に置いてアプリとして起動できる
- **本番環境を用意してデプロイする。** Cloudflare Workers（workers.dev のサブドメイン）、本番の D1、シークレットの登録
- **デプロイ手順を文書化する。** 次に自分がやるときに迷わない程度に

### 先行実装から引き継ぐ教訓

先行実装のデプロイコマンドは `opennextjs-cloudflare build && deploy` で、**テストを一度も走らせずに出荷できた**。この change ではデプロイの手前でテスト・型チェック・ビルドを通し、失敗したら進まないようにする。

### 今回やらないこと

| 除外するもの | 扱う change |
|---|---|
| プッシュ通知、Service Worker の通知処理 | change 4 |
| 問と答の AI 生成 | change 5 |
| タグ、メモ詳細画面 | change 6 |
| 独自ドメイン | 必要になったら別途 |
| オフライン対応・キャッシュ戦略 | 対象外 |

PWA シェルは manifest とアイコンまでとし、**Service Worker は change 4（通知）で入れる**。Service Worker はプッシュ通知のためのものなので、使う change と同時に入れる。

## Capabilities

### New Capabilities

- `accounts`: 利用者がアカウントを作り、サインインし、サインアウトできること。および、そのセッションから利用者を一意に識別できること。認証基盤の実装詳細（どの事業者を使うか）はこの capability の関心事ではない

### Modified Capabilities

- `memo-capture`: メモが認証済みの利用者に紐づき、他の利用者から到達できないこと
- `quiz-item`: 問と答が、そのメモを持つ利用者だけのものであること
- `review-session`: 出題対象と自己採点が、その利用者のものだけに限られること

`review-scheduling` は利用者の概念を持たないため変更しない。

## Impact

**コード** — `SINGLE_USER_ID` を参照している箇所（`lib/memos.ts`、`lib/quiz-items.ts`、`lib/review.ts`、および API のルート）が、セッションから導出した識別子を受け取る形になる。ドメイン層の関数はすでに `userId` を引数で受け取っているため、変更は呼び出し側に閉じる。

**データ** — スキーマ変更なし。`userId` 列は change 1 から存在し、固定値が入っている。**既存のローカルデータは持ち主が居なくなる**が、開発中のテストデータのみなので破棄してよい。

**画面** — サインイン・サインアップの画面が加わる。未認証時はそこへ誘導される。

**依存関係** — Clerk の SDK を追加する。

**秘密情報** — この change で初めてシークレットを扱う。**このリポジトリは public** であり、鍵をコミットすれば公開時点で漏洩する。`.gitignore` は change 1 で `.env*` / `.dev.vars*` を除外済み。実際の値は Cloudflare のシークレットストアに置く。

**費用** — Clerk と Cloudflare の無料枠を前提とする。公開サインアップにしたため、利用者が増えれば枠を超えうる。`docs/intent-statement.md` に未確定事項として記録済み。
