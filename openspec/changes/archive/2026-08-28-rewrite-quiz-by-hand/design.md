実測した現状:

| | 幅 × 高さ | 色 |
|---|---|---|
| つくり直す | 60 × **21px** | `--ink-soft` |
| 消す | 44 × **30px** | `--ink-soft` |
| 戻る | 44 × 44px | `--ink-soft` |

アプリの他6箇所は 44px を確保している。**この2つだけが確保していない。**
`.detail-foot` は `display:flex; gap:1rem` なのに子が1つで、change 7 で
シートから全画面にしたときの残骸である。

既にあるもの:

- `QuizSheet` — 手で問と答を書くシート。**未作成のときだけ**開く
- `PUT /api/memos/[memoId]/quiz-item` — いまは AI で作り直す
- `POST` — 手で作成する。既にあると `already_exists` で弾く

## Goals / Non-Goals

**Goals:**

- 生成が外したとき、利用者が自分の言葉で直せる
- 取り消せる操作と取り消せない操作を、形と色で分ける
- 的を 44px 以上にする

**Non-Goals:**

- 復習画面での書き直し（そこは思い出す場であって、直す場ではない）
- メモ本文の編集（この change では触らない）
- 生成そのものの改善（プロンプト・モデル）

## Decisions

### D1: 答えを隠すのをやめる。**隠しても守れていなかった**

`memo-capture` には「答えを示しては MUST NOT ならない。開いた時点で答えが
見えると、想起の機会そのものが失われる」とあった。だが生成の指示は
`lib/quiz-generation.ts` にこうある。

```
答えはメモから読み取れる事実だけにします
```

そして詳細画面は、**そのメモの本文を上部に全文出している**。

```
┌────────────────────────┐
│ 味噌汁は沸騰させない    │ ← 本文。答えはここから読み取れる
├────────────────────────┤
│ 問：…避けることは？     │
│ 答：（隠す）            │ ← ここだけ隠しても遅い
└────────────────────────┘
```

**隠していたのは欄であって、内容ではない。** change 7 の判断は覆したのでは
なく、もともと成立していなかった。

答えを出すと、書き直しの対象が画面に揃う。押す前に見えているものと、
シートに出てくる欄が一致する。

### D2: 置き方は K。**札を作らず、「タグ」と同じリズムに並べる**

3案（札にする／見出しの隣／問が主・答が従）を実機で比べて K を採った。

```
復習                        ✏     ← 鉛筆は見出しの隣
問  味噌汁を煮るときに…            ← オレンジの版（1版目）
答  沸騰させること                 ← インクブルーの版（2版目）
次は 8月29日                       ← 版なし。書き直しの範囲外
```

札を足さないので、`タグ` と同じ骨格のまま縦に伸びない。**2版を問と答に
1つずつ割り当てる**のは、自己採点の2択と同じ使い方（`docs/design-decisions.md`）。

日付に版を当てないことで、**書き直しが触らないもの**が形の上で分かれる。

### D3: 消すは上の帯へ。`--danger` を当てる

`.detail-foot` は子が1つで、`gap` が働いていない。下に置く理由が既に無い。

```
←                        消す    ← 上の帯。danger 色
```

「メモ」という見出しは落とす。**戻る矢印と本文があれば、どの画面かは分かる**
（change 8 の基準「見れば分かることは書かない」）。

確認シートは変えない。「起動した消すと実行の消すが同じ場所に出ない」は
`memo-capture` の要件（change 9）で、上に移しても守られる ―
シートは下から出る。

### D4: 鉛筆は印だけ。文字を添えない

鉛筆は**自分で書き換える**を意味する。この change でそれが本当になったので、
印がそのまま通る。ソフトウェアで最も広く知られた印であり、このアプリで
3つ目の印になる（`←` と `×` に続く）。

読み上げ名は「問と答を書き直す」を残す。`docs/design-decisions.md` の
「ラベルは短いほど読ませない。ただし**読み上げ名は短くしない**」に従う。

### D5: `PUT` を作り直しから書き直しへ。生成の経路は消す

| | いま | これから |
|---|---|---|
| `POST` | 手で作成（既にあると `already_exists`） | 変えない |
| `PUT` | **AI で作り直す** | **手で書き直す**（問と答を受け取る） |

`lib/quiz-generation-run.ts` の `replaceExisting` は使われなくなるので消す。
**モデルの呼び出しが1経路減る。**

書き直しは `review_schedules` に触れない。`quiz_items` の question と answer
だけを更新する。触らないことが、進み具合を保つことの実装そのものになる。

### D6: シートは `QuizSheet` を使い回す。初期値を受け取れるようにする

新しい画面を作らない。いまのシートに初期値と保存先を渡せるようにするだけで、
**検証（空でない・長さの上限）も失敗時に入力を残す挙動もそのまま効く**。

```
QuizSheet
  ├ 作成（初期値なし、POST）      ← いまの使い方
  └ 書き直し（初期値あり、PUT）   ← 足す
```

## Risks / Trade-offs

- **生成が外したとき、もう一度振る手段が無くなる** → 意図した割り切り。
  手で書くほうが速くて確実で、費用もかからない（proposal.md）。
- **答えが常に見えるので、詳細を開くと思い出す機会が減る** → 本文が既に
  上に出ているので、実質は変わらない（D1）。それでも減る分はある。
- **`PUT` の意味が変わる** → 外部に公開している API ではないので、画面と
  同時に差し替えれば足りる。
- **鉛筆が3つ目の印になる** → 意味が広く知られた印に限る、という線は保つ。
