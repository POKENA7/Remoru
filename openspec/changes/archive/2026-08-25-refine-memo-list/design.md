## Context

動機は `proposal.md` の `## Why`、要件は `specs/` を参照。

**制約1: 下部タブは「メモ」と「復習」の2つのまま増やさない**（`docs/design-decisions.md`）。

**制約2: 通知の設定はすでに全画面で成立している。** `app/notification-settings.tsx` は
下部タブの中身を差し替える形で、上に「戻る」を置いている。URL も増やしていない。
**この形が先例としてある。**

**制約3: データ層と API は変えない。** `GET /api/memos` はいまも本文・タグ・
復習状態（問と次回出題日を含む）を返す。変わるのは画面が使う範囲だけ。

## Goals / Non-Goals

**Goals:**

- 一覧を「探す」ためだけの形に戻すこと
- 詳細に情報が増えても入るようにすること
- 既存の振る舞い（絞り込み・タグの付け外し・削除・作り直し）を落とさないこと

**Non-Goals:**

- 復習の仕組みへの変更。出題の対象・順序・間隔・通知には触らない
- API・データ層の変更
- 一覧の並び替えや検索。絞り込みは change 6 のまま

## Decisions

### D1: 詳細は全画面にする。change 6 の D3 を差し替える

`app/notification-settings.tsx` と同じ形にする。下部タブの中身を差し替え、
上に「戻る」を置く。下部タブも URL も増えない（制約1・制約2）。

**change 6 の D3 は判断を誤っていた。** そこでは「独立した画面に遷移する」を
「戻る操作の受け皿が要り、下部タブとの関係も曖昧になる」として却下したが、
通知の設定がすでにその両方を解いている。**選べたはずの形を、無い選択肢として
退けていた。** `docs/design-decisions.md` の予告も「メモ詳細画面」だった。

*代替案*: シートのまま情報を増やす。却下。タグの入力欄とソフトウェア
キーボードがぶつかる問題が残り、情報を移すほど窮屈になる。

*代替案*: 行をその場で展開する。却下。削除のような取り消せない操作を
一覧に戻すことになる。change 6 の D4 で外したばかり。

### D2: 一覧の行は本文・タグ・状態の印だけにする

行のどこを押しても詳細が開く。「くわしく」のボタンは無くす。

*代替案*: 「くわしく」を残す。却下。行全体が押せるなら、押せる場所を
指す小さな的を別に置く理由が無い。

### D3: 状態は色ではなく形で示す

3つの状態を印で描き分ける。**色の違いだけに頼らない**（spec の要件）。

| 状態 | 印 |
|---|---|
| 問と答があり、出題日が決まっている | 塗りつぶした丸 |
| 作っている最中 | 点滅する丸（`prefers-reduced-motion` では点滅しない） |
| 未作成 | 輪郭だけの丸 |

印には読み上げ用の説明を付ける。形だけでは触読・読み上げに届かない。

### D4: 次回の出題日は詳細に置く

一覧で要るのは「何が書いてあるか」であって「いつ出るか」ではない。
その日に何を復習するかは**復習タブが持っている**（件数と進捗マス）。
一覧に日付を並べても、そこから復習は始められない。

### D5: 詳細でも答えは出さない

一覧に答えを出さない理由（開くだけで想起の機会が失われる）は、詳細でも
同じ。詳細を開くのは意図した操作だが、**メモを探しに来ただけで答えまで
見えるのは望んでいない**。

`GET /api/memos` は答えを返していないので、画面側で足さなければよい。

### D6: 戻ったら絞り込みは保つ

絞り込みは `app-shell` のクライアント状態で、詳細を開いても消えない。
詳細は一覧を**差し替える**のであって、一覧の状態を捨てるわけではない。

### D7: 詳細が指すメモは id で保持する

いまは一覧の配列から `find` して導いており、**絞り込み中にタグを外すと
そのメモが一覧から消え、画面が無言で閉じる**（change 6 のレビュー 軽微-7）。
全画面にすると「開いていたものが勝手に閉じる」はより不自然なので、
詳細が自分でメモを保持する形にする。

## Risks / Trade-offs

- **[一覧から出題日が見えなくなる]** いつ復習が来るか一覧で分からない →
  D4 のとおり復習タブが持っている。使ってみて足りなければ、印に色の濃さで
  近さを載せる余地はある
- **[行全体が押せると誤って開きやすい]** → 詳細は読むだけの画面で、
  削除にはさらに確認がある。誤って開いても失うものは無い
- **[印だけでは状態が伝わらない]** → 形を変え、読み上げ用の説明を付ける。
  コントラストは実測する
- **[画面遷移が1つ増える]** タグを付けるのに一覧→詳細の2手 → もともと
  change 6 から2手だった（シートも遷移である）。手数は変わらない

## Migration Plan

1. 詳細を全画面に作り替える（シートを廃止）。中身は現状＋問・出題日・作り直し
2. 一覧の行を削り、行全体を押せるようにする
3. 状態の印
4. コントラストを実測する
5. デプロイ

**ロールバック**: 画面の変更だけなので、前の版に戻せば足りる。データにも
API にも触らない。
