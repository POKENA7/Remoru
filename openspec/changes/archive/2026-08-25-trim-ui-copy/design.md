## Context

動機と数値は `proposal.md` を参照。spec の変更は無い。

**制約1: `docs/design-decisions.md` は5つの言い回しを「変更しないこと」と
確定している。** 思い出せなくても大丈夫／つづきはまた、そのうち。／
気が向いたときで／おしまい／開かなくても、たまっていきます。

**制約2: 消せない説明がある。** iOS はホーム画面に追加した PWA でしか通知を
受け取れない。これは画面からは分からず、書かなければ伝わらない。

**制約3: 読み上げの利用者にとって、ラベルの短縮は情報の削減になりうる。**
`←` だけにすると、視覚的には十分でも読み上げでは何も言わない。

## Goals / Non-Goals

**Goals:**

- 常時目に入る説明文を減らすこと
- 責めない語り口を保つこと（減らす対象と混同しない）
- 読み上げで失われるものを作らないこと

**Non-Goals:**

- エラー文の削減。**出るときにしか出ない**ので、常時の疲れには寄与しない
- 画面構成・操作の変更。この change は文言だけを扱う
- トーンの見直し。確定した言い回しは触らない

## Decisions

### D1: 「トーンの文」と「説明の文」を分けて、後者だけを削る

同じ短い1行でも、役割が違う。

| 種類 | 例 | 扱い |
|---|---|---|
| トーン | 気が向いたときで／思い出せなくても大丈夫 | **残す**（制約1） |
| 説明 | 1枚見るたび、ひとマス刷られます | 削る |
| 制約の告知 | iPhone・iPad では…届きません | **残す**（制約2） |
| ラベル | つくり直す／消す | 短くする |

この切り分けがあるので、確定リストを蒸し返さずに済む。**「文字を減らす」を
一律に適用すると、責めない語り口まで削れてしまう。**

### D2: ラベルは短くするが、読み上げ名は短くしない

`戻る` を `←` にするとき、`aria-label="戻る"` を付ける。見た目の文字数だけを
減らし、読み上げに渡る情報は変えない（制約3）。

*代替案*: ラベルもそのまま残す。却下。利用者が明示的に「ラベルの短縮まで
踏み込む」と決めている。

*代替案*: アイコンを画像にする。却下。1文字で足りるものに資産を増やさない。

### D3: 削った説明を「初回だけ表示する」形にはしない

「1枚見るたび、ひとマス刷られます」を初回だけ出す案は自然に見えるが、採らない。

- **見たかどうかの状態を持つ必要がある**（端末ごとか利用者ごとかの判断も要る）
- 初回に読んでいる保証は無く、読まなかった人には二度と出ない
- そもそもマスは見れば分かる。**初回にも要らない**

削るものは、初回にも要らないものだけにする。

### D4: 文言の規則は `docs/design-decisions.md` に置く

spec は振る舞いを定める場所で、文言は入っていない。一方、コピーのトーンと
確定した言い回しはすでに design-decisions にある。**同じ判断が2箇所に分かれる
のを避ける。**

### D5: 確定リストから「開かなくても、たまっていきます」を外す

`docs/design-decisions.md` が「変更しないこと」として挙げている5つのうち、
これだけ**一度も実装されていない**（change 1 から現在まで、どの画面にも無い）。

いま実装すれば説明文が1つ増える。この change の向きと逆なので、**確定リストから
外し、外した記録を残す**。書きたくなったときに、また置けばよい。

## Risks / Trade-offs

- **[説明を消したことで操作が分からなくなる]** とくに「つけかえると、いまの
  タグは外れます」→ 付け替えを一度もしたことがない人は、いまのタグが
  残ると思うかもしれない → **付け替えれば即座に結果が見える**（画面のタグが
  入れ替わる）。取り返しもつく（また付け替えられる）。取り消せない操作では
  ないので、先回りしない側に倒す
- **[`←` が分かりにくい]** → 読み上げ名は「戻る」のまま。視覚的にも、上部
  左端の `←` は広く通じる形
- **[消しすぎて素っ気なくなる]** トーンの文を残す判断（D1）がこれを防ぐ。
  実装後に画面を見て、寒々しければ戻す
- **[この判断が次の change で忘れられる]** → D4 のとおり design-decisions に
  書く。それでも、説明文は書き足したくなるものなので、完全な防止にはならない

## Migration Plan

1. 画面ごとに文言を差し替える
2. コントラストと読み上げ名に影響が無いことを確認する
3. `docs/design-decisions.md` に規則を書き、確定リストを整理する
4. デプロイ

**ロールバック**: 文言だけなので、前の版に戻せば足りる。
