## Purpose

利用者がアプリを開いてから使い始められるまでの速さの要件を定める。速さの定義と
測り方は `docs/perf.md` に置き、この spec はその定義を借りる。何を速くするかは
各画面の capability が定め、ここでは「どれだけ速いか」だけを定める。

## ADDED Requirements

### Requirement: 一覧が読めるまでの時間

システムは、サインイン済みの利用者が `/` を開いてから、一覧の最初のメモの本文が
画面に描かれるまでを **1 秒以内**に SHALL する。条件は `docs/perf.md` の
「ウォーム」の条件（利用者の iPhone、PWA、Wi‑Fi、一度開いて閉じたあとの再起動）と
SHALL する。

コールド（Workers の起動を含む）はこの要件の対象外とする。記録は残す。

#### Scenario: 再起動して一覧を開く

- **WHEN** サインイン済みの利用者が、一度開いて閉じたアプリをホーム画面から再び開く
- **THEN** システムは 1 秒以内に一覧の最初のメモの本文を描く

#### Scenario: 速さの主張は同じ手順の計測で裏づける

- **WHEN** 速くする変更を本番に出そうとする
- **THEN** `docs/perf.md` の手順で変更の前後を 5 回ずつ測った記録が存在し、後の中央値が前の中央値を下回っている

### Requirement: タブの切り替えは待たせない

システムは、下部のタブをタップしてから切替先の画面が描かれるまでの時間を、
`docs/perf.md` に記録された基準値（2026-09 時点のクライアント状態による切替）と
同等に SHALL 保つ。画面の構成を変える変更が、この値を目に見えて悪化させては
MUST NOT ならない。

#### Scenario: 経路を分けても切替が遅くならない

- **WHEN** タブがそれぞれ固有の経路を持つ形に変えたあと、利用者がタブをタップする
- **THEN** 切替先の枠は即座に現れ、中身が描かれるまでの時間の中央値は基準値と同等である

### Requirement: 転送量の予算

システムは、`/` を開くために読み込むクライアント JavaScript の gzip 合計を、
`scripts/harness/bundle-budget.json` に置いた予算以内に SHALL 保つ。予算を超える変更は
検査で止め SHALL る。

#### Scenario: 予算を超えるとコミットできない

- **WHEN** 変更によって `/` のクライアント JavaScript の gzip 合計が予算を超える
- **THEN** `npm run check` は非ゼロで終わり、超えた量と内訳を示す
