# デザイン判断の記録

2026-08-23 に Claude Design を用いて確定させたもの。change 2 以降の画面設計は
ここを起点にする。未確定事項は `docs/intent-statement.md` を参照。

**キャンバス**: https://claude.ai/design/p/5928c519-aafa-4ea8-8ba0-48a4975c94d5
（「リソグラフと情報カード」。turn 0 = 採用案 2a、turn 1 = 検討した3案の履歴）

## 美的方向: リソグラフ重ね刷り

3案（リソグラフ / 紙の情報カード / 夜基準の「灯り」）を出させて比較し、
**リソグラフ重ね刷り**を採用した。

- 蛍光オレンジとインクブルーの**2版**。版ズレ、紙の粒子、角丸のインク面
- 地はクリーム。ダークモードは「夜の紙」で、重ね刷りを multiply ではなく
  screen に反転させ、インクが光る側に回る（単なる色反転ではない）
- 和文フォント。Inter / Roboto、紫グラデーション、企業SaaS風は使わない

採用理由: 暖色・ポップ・進捗が視覚的にわかりやすい、の3条件を満たしたのが
これだけだった。「紙の情報カード」はメタファーが言語を食っていた（「束を戻し
ました」「抜く札がありません」）。「灯り」は最も美しいが夜基準で暖色ではない。

## 確定した操作設計

| 論点 | 決定 |
|---|---|
| 自己採点 | **2択のみ**（覚えてた / 忘れてた）。3段階以上にしない |
| 採点ボタンの重み | **等価**。2版を1つずつ割り当て（忘れてた=青、覚えてた=橙） |
| 復習の見せ方 | **全画面カード1枚ずつ**。一覧形式にしない |
| 進捗 | マス目が塗られる（＝刷り上がった枚数）。上限10マス |
| 画面構成 | 下部タブ2つ（メモ / 復習）。タブを増やさない |
| 答えの提示 | 最初は隠す。「答えを見る」で開く |
| 問と答の作成 | **メモ保存の直後**に続けて。「あとで」でスキップ可 |

### 自己採点が2択で、かつ等価でなければならない理由

この2択はスケジューラの唯一の入力で、次回の出題日を決める。押しやすい側に
自己申告が偏ると、記録も出題間隔も歪む。「正解が推奨されている」と読める形を
作らないこと。将来 SM-2 系の適応アルゴリズムに差し替える場合、2択では情報が
落ちるため UI 変更が必要になる。それを承知で2択を選んでいる（手数を優先）。

### 進捗マスの規則

マスは最大10個。10枚までは1マス＝1枚。11枚以上はマス数を10に固定し、
1マス＝2枚・5枚…と束ねる。1枚見るごとにマスが途中まで塗られる（部分塗り）。
溢れない・潰れないことが要件。

## 漢字とひらがなの使い分け

日本語は分かち書きをしないので、**漢字が語の切れ目を作っている**。名詞や数量まで
ひらがなにすると読み速度が落ちる。片手で数十秒という利用文脈では、この一拍が効く。

- **漢字**: 名詞・数量・日付・時制（枚、次は、今日は、新しい順、書きとめたもの、戻る）
- **ひらがな**: 動詞と語尾のやわらかさを担う語（はじめる、あとで、これでいい、
  やめる、**おしまい**、ひとことでいい、なにか書きとめる）

やわらかさは語彙の選択（「開始」ではなく「はじめる」）で担保する。表記をかなに
開くことで担保しようとしない。

## コピーのトーン

**勉強アプリに見えないこと。** 義務感、達成率、連続記録、ランク、煽り、成績表は
出さない。忘れていても責められない。1日サボっても何も言われない。

確定している言い回し（変更しないこと）:

> 思い出せなくても大丈夫 / つづきはまた、そのうち。 / 気が向いたときで /
> おしまい

※ change 8 で「開かなくても、たまっていきます」を確定リストから外した。
**5つのうちこれだけ一度も実装されていなかった**（change 1 から change 7 まで
どの画面にも無い）。いま実装すれば説明文が1つ増え、文言を削る方針と逆を
向く。書きたくなったら、また置けばよい。

## 画面に置く文の量

**このアプリはメモアプリで、画面はすでに利用者自身の文章で埋まる。** そこに
機能の説明を重ねると、読む量が二重になる。

change 8 の時点で、枠の文言 408字のうち **220字（54%）が説明文**だった。
とくに「復習・開始前」は 66% が説明で、しかも復習のたびに読まされていた。

**同じ短い1行でも役割が違う。混ぜて扱わないこと。**

| 種類 | 例 | 扱い |
|---|---|---|
| トーン | 気が向いたときで／思い出せなくても大丈夫 | **残す**（上の確定リスト） |
| 説明 | 1枚見るたび、ひとマス刷られます | 置かない |
| 制約の告知 | iPhone・iPad では…届きません | **残す**（画面から分からない） |
| ラベル | つくり直す／消す | 短くする |

「文字を減らす」を一律に適用すると、責めない語り口まで削れる。

説明を置かない基準は3つ。

1. **見れば分かることは書かない。** 進捗マスの説明、「ぜんぶ」に戻せること、
   見出しと同じ内容の補足
2. **先回りせず、起きてから見せる。** 「つけかえると、いまのタグは外れます」は、
   付け替えれば結果が見える。取り消せない操作（削除）の確認文は例外で、
   **これは残す**
3. **ラベルは短いほど読ませない。** ただし**読み上げ名は短くしない**。
   `←` には `aria-label="戻る"` を付ける

**「初回だけ表示する」形は採らない。** 見たかどうかの状態を持つ必要があり、
初回に読んでいる保証も無い。削るのは初回にも要らないものだけにする。

## コントラスト

ライト・ダーク両モードで、本文・補助文字・ボタン・エラーのすべてが 4.5:1 以上。
実測で確認する（意図ではなく計算値で確かめる — `.learnings/active.md` L04）。

| | ライト | ダーク |
|---|---|---|
| 覚えてた（白文字／橙） | 4.74 | 4.85 |
| 忘れてた（白文字／青） | 7.92 | 6.35 |
| 答えを見る（白文字／青） | 7.92 | 6.35 |

明るい地に白文字を載せると基準を割る。蛍光インクは彩度も明度も高いので特に注意。

## 画面の一覧（設計済み）

change 2 の範囲: 1〜7。ライト・ダーク各7画面が 2a に描かれている。

1. メモ投入と一覧
2. 問と答の作成（一覧の「問と答をつくる →」から・背後は一覧）
   ※ change 5 以降、保存直後にはせり上がらない。問と答は生成が作る
3. 今日の復習・開始前
4. 出題・答えを見る前
5. 出題・答えを見た後（自己採点）
6. 復習完了
7. 復習が0件のとき

**画面4と5でカードの高さは同じ。** 画面4の空白は答えが入る予約領域であり、
めくったときにレイアウトを跳ねさせないための設計。埋めないこと。

## 設計済みだが change 2 の範囲外

- **タグ機能**（change 6）— タグの表示・単一選択フィルタ・手動付与（保存直後と
  メモ詳細の両方）・AI によるタグ提案（未分類がたまったら帯が出る／承認は
  **タグ名と件数だけ**で、どのメモに何が付いたかは確認させない）
  ※ **手動付与の「保存直後」は無くなった。** change 5 で保存直後のシートを
  やめたため（問と答は生成が作る）。付与はメモ詳細だけになる
- **メモ詳細画面** — タグ機能と同時に必要になる。メモの削除もここに置く
  ※ change 6 で**削除は一覧から詳細へ移す**。一覧の行にタグが加わるので、
  取り消せない操作を同じ行から外す
  ※ change 6 では詳細をシートで出したが、change 7 で**全画面に戻した**。
  「画面」という当初の予告が正しかった。通知の設定と同じ形で、下部タブも
  URL も増やさずに成立する

## change の並び

```
change 2  復習ループ（手書きの問答 + 固定間隔）  ← 次
change 3  デプロイ + 認証
change 4  通知
change 5  AI による問答の生成       ┐ 同じ技術基盤
change 6  AI によるタグ提案 + タグ  ┘
```

5 と 6 は プロンプト構築・応答パース・失敗時の劣化・呼び出し回数の制御が共通。
6 を 5 のあとに置くと安く済む。
